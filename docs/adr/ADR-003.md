# ADR-003 (WP-00 draft): Event-sourced authoritative state; PostgreSQL as the future authority

- Status: DRAFT (WP-00 baseline) — confirms adopted ADR-0003 + constitution §5.2
- Context: State must advance only via events, record actor/inputs/outputs/time/
  reason, be rebuildable from an immutable log, and never change by silently editing
  one JSON file (req spec §7).
- Decision: Keep project state as a **projection of an append-only event log**.
  Current adapter is JSONL on disk (`core/store.py`) + JSONL ledgers
  (`execution/runs.py`); **PostgreSQL is the future authoritative event store**
  (with outbox + optimistic concurrency) behind `EventStorePort`. SQLite/JSONL are
  only for local/test/early adaptation, never the final source of truth
  (constitution §5.2).
- Consequences: Domain logic depends only on append/load/rebuild; swapping to
  Postgres (WP-03) changes no domain code. `DatasetManifest` is immutable once
  locked — changes create a new version.
- Cross-refs: adopted ADR-0003; ADR-004; constitution §2.12, §5.2; req spec §7.
- Open items: JSONL store has no concurrency lock (acceptable single-process;
  resolved by Postgres adapter).
