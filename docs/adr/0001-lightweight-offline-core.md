# ADR-0001：轻量离线核心优先于重型基础设施

- 状态：已采纳
- 背景：需求规格 v0.1 要求"离线确定性、一条真实纵向切片"；架构落地计划 v1.0 要求 PostgreSQL+MinIO+Nextflow+队列+Docker Compose。两者在落地深度上冲突。
- 决策：本次按**轻量离线核心**落地（Python + dataclass + JSON/JSONL，运行期仅依赖 numpy），把 v1.0 的重型基础设施作为未来目标、以端口预留（见 ADR-0004）。
- 理由：①v1.0 的外部服务与"默认测试必须离线、不联网、不调付费 LLM、可重复"直接冲突；②一次性铺开 28 个工作包会变成相互依赖的空壳，违反"别搭空壳、先打通一条可运行可测试的纵向切片"的纪律；③轻量核心可被第三方零摩擦复现（只需 numpy）。
- 后果：本次不具备水平扩展/多用户/分布式执行；但领域核心不绑定任何外部服务，升级时不改状态机。
