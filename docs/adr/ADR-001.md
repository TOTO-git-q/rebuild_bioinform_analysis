# ADR-001 (WP-00 draft): Audit-first, rebuild on the cleaned core (not greenfield)

- Status: DRAFT (WP-00 baseline) — confirms decision D-01
- Context: Two routes were possible — greenfield rewrite vs. evolve the existing
  `auto_bioinfo` rebuild. The current `auto_bioinfo/core/` is the cleaned
  canonical control-plane domain core (see adopted ADR-0002), is stdlib/numpy-only,
  carries the safety rails, and passes 113 offline tests.
- Decision: Do a read-only audit first (WP-00), then build forward by **preserving
  and extending** the clean core and **replacing offline adapters with production
  adapters behind unchanged ports** — never a wholesale greenfield rewrite.
- Consequences: Reusable assets (core schemas, state machine, event store, QC,
  alignment auditor, reproduction bundle) are kept; growth is additive (new schema
  fields, new methods, new adapters). Retired predecessor anti-patterns must not
  return (see `docs/audit/preserve_replace_retire.yaml`).
- Cross-refs: adopted ADR-0002; D-01; `docs/audit/repository_inventory.md`.
- Open items: none blocking. Numbering coexistence with adopted `0001..0007`
  handled in ADR-010.
