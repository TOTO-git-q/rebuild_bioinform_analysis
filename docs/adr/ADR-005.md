# ADR-005 (WP-00 draft): Schema-first / contract-first before business logic

- Status: DRAFT (WP-00 baseline) — supports req spec §3.4 and plan WP-02
- Context: Every key stage must emit a structured object; prose cannot replace
  structured output (req spec §3.4). The audit found several schemas present but
  field-incomplete vs. the spec (SubQuestion, EvidencePlan, DatasetProfile, TaskRun)
  and some objects missing (DatasetFeasibilityReport, OriginalRequest/ProjectPolicy,
  AmbiguityReport, OntologyMapping, QuestionDependencyGraph).
- Decision: Fix machine-readable schemas/enums + semantic validators **before**
  implementing the agents/API/DB logic that depend on them (plan WP-02). Each schema
  ships with JSON Schema + positive/boundary/negative examples and a compatibility
  checker; breaking changes require a new major version.
- Consequences: Downstream WPs (06–22) bind to stable contracts; the gap_matrix
  drives which fields/objects WP-02 must add (priority = MUST first).
- Cross-refs: req spec §3.4, §5; plan WP-02; `docs/baseline/requirements_catalog.csv`,
  `docs/audit/gap_matrix.csv`.
- Open items: schema-version constant currently `v5.canonical/0.1`; unify versioning
  when schemas are extended (do not break the claim-ceiling invariant).
