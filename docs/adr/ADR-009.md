# ADR-009 (WP-00 draft): Config + secret model — env / non-sensitive config / secret reference

- Status: DRAFT (WP-00 baseline) — supports plan WP-01 (T-01-03) + constitution §2.10/§7
- Context: The system needs a unified configuration model that cleanly separates
  environment variables, non-sensitive config, and **secret references**, with
  fast-fail on missing required config and **no secrets committed to the repo**.
- Decision: Adopt a layered settings model (built in WP-01): (a) non-sensitive
  config in versioned files; (b) environment variables for deployment-specific
  values; (c) secrets only by *reference* (e.g. env name / secret manager key),
  never inline. Logs must redact tokens. Robot credentials stay least-privilege
  (per-repo, per-task); no org-level or cross-repo scope; no global plaintext
  credential store.
- Consequences: Missing required config fails fast; secrets never enter git history,
  turns, or logs. This is a forward decision — no config/secret framework exists in
  the codebase yet (gap REQ-SEC-01/03).
- Cross-refs: constitution §2.10, §7; plan WP-01 T-01-03, WP-23; req spec §10.
- Open items: implementation deferred to WP-01/WP-23; WP-00 changes nothing here.
