# ADR-002 (WP-00 draft): Modular-monolith control plane + separate execution workers

- Status: DRAFT (WP-00 baseline) — confirms constitution §5.1 default
- Context: The system must remain operable beyond a single laptop (constitution
  §5.4) but must not fragment into many microservices this stage.
- Decision: Adopt a **modular monolith control plane** (project/state/event/approval/
  query) with **separate execution workers** for analysis/workflow/engineering tasks.
  Today the worker runs in-process (`pipeline.py:_execute`); the boundary is kept
  explicit so workers can later be isolated/containerized without changing the core.
- Consequences: Clear control-plane vs data-plane split now; horizontal scaling and
  queue/broker (WP-03/WP-13/WP-14) are additive. The control plane never executes
  scientific code directly — it dispatches to a method/worker behind a port.
- Cross-refs: ADR-004 (ports); constitution §5.1/§5.7; req spec §4, §8, §11.
- Open items: isolated/sandboxed worker + queue not yet built (gap REQ-STG-11).
