# ADR-006 (WP-00 draft): Nextflow as the first workflow adapter; reproducible execution

- Status: DRAFT (WP-00 baseline) — confirms decision D-06 + constitution §5.3/§5.7
- Context: Scientific execution must be reproducible and not bound to one machine.
  The offline reference method (`bulk_deg`) runs in-process and numpy-deterministic
  (adopted ADR-0006); production needs containerized, schedulable workflows.
- Decision: **Nextflow is the first production workflow adapter** behind
  `AnalysisMethodPort`, running the *same* MethodContract as the in-process method.
  The control plane owns approval, event recording, dispatch and status; Nextflow
  owns reproducible execution.
- Consequences: Real tool-chains (limma/edgeR/scanpy) enter as containerized
  Nextflow methods (route WP-14/WP-16/WP-17) without changing the domain core. The
  offline numpy method stays as the deterministic, dependency-light default and test
  baseline.
- Cross-refs: D-06; adopted ADR-0006; constitution §5.3/§5.7; ADR-004.
- Open items: Nextflow integration not implemented this stage (reserved).
